# ADR-0019 公理是一等公民，OWL 是词汇而非推理机

- 状态：Accepted
- 日期：2026-08-24

## Context

GB/T 48000.3—2026《标准数字化 第3部分：本体建模要求》（2026-01-28 发布，
2026-08-01 实施）规定一个完整本体至少包含五大组件：
实体类型、数据属性、对象属性、**公理**、规则。

逐项核对本平台，四项已具备，且部分强于标准要求：

| 标准组件 | 本平台 | 情况 |
|---|---|---|
| 实体类型 | `business_object` + `type_hierarchy` | 有，且带声明式继承 |
| 数据属性 | `business_attribute` | 有，且带单位与派生表达式 |
| 对象属性 | `business_relation` | 有，且带基数与强弱 |
| 规则 | `business_rule` + `rule_sandbox` | 有，且带留痕与治理门禁 |
| **公理** | — | **缺** |

两处需要澄清，因为它们看起来像差距而其实不是：

**Domain 与 Range 一直都有。** `business_relation.source_object_id` 与
`target_object_id` 就是 domain 和 range，且都是指向 `business_object` 的外键——
比标准要求更强，因为数据库层面就无法指向一个不存在的类。
缺的不是能力，是**用一个外部工具认得的词说出来**。

**发布门禁一直在做 SHACL 想做的事**，而且更严：待审映射无法用 `--force` 跳过。
缺的同样不是能力，是可交换的形式。

真正的两处缺口因此是：公理这一组件，以及标准词汇这一表达层。

## Decision

### 一、公理独立于规则，在建模期校验，违反阻断发布

公理与规则回答不同问题，混为一谈有具体代价。

- **规则**对实例求值：「这份合同金额超过该客户额度，阻断」。需要数据，逐实例运行。
- **公理**断言模型本身：「合同的甲方与乙方永远不能是同一主体」。不需要数据，
  每个模型版本校验一次。

把后者写成规则，它会在每次判定时对每个实例重算，而且**只能报出一个违规实例，
永远报不出真正的问题**——问题是模型允许了一种业务上不存在的形状。
更糟的是，一个自相矛盾的模型此前照样能发布：没有任何门禁看过
「这些声明能不能同时为真」。

因此公理在**建模期**校验，且**违反是阻断而非警告**——
一个自相矛盾的模型产出的每个判定都可疑，「明知矛盾仍发布」不是应该提供的选项。

**声明期与发布期都检查**，因为二者拦的失效模式不同。声明期检查让写公理的人
立刻看到矛盾；发布期检查抓的是声明期看不到的情况——公理写下时成立，
之后**模型在它下面变了**：加了子类型、关系改了指向、属性改成可空。

六类公理，全部只用已声明结构即可判定：
`disjoint_types`、`irreflexive_relation`、`asymmetric_relation`、
`functional_relation`、`required_attribute`、`disjoint_attributes`。

**公理引用不存在的对象时拒绝，而非警告。** 一条引用了拼错关系名的公理
是恒真的——它什么都不约束、什么都不报，于是建模者相信有一道控制而其实没有。
这比没有公理更糟。

### 二、采用 OWL/RDFS/SHACL 作为词汇，继续拒绝 DL 推理

平台此前已导出 JSON-LD 与 Turtle，但那不构成互操作：**语法是标准的，
每个术语都是自造的**。懂 OWL 的消费方知道 `rdfs:domain` 的含义并能据此行动，
它无法知道 `ont:sourceObject` 是同一件事。于是导出是机器**可读**而非机器**可解释**的，
而标准要解决的正是后者。

映射而非替换。`ont:` 导出保留，因为它有下游，且承载标准词汇无对应词的字段
（来源表、规则表达式、映射置信度）。为了「标准纯粹」丢掉这些，
会丢掉让导出对本平台自身有用的信息。

| 平台概念 | 标准术语 |
|---|---|
| 业务对象 | `owl:Class` |
| 业务属性 | `owl:DatatypeProperty` + `rdfs:domain` + `rdfs:range` |
| 业务关系 | `owl:ObjectProperty` + `rdfs:domain` + `rdfs:range` |
| 子类型声明 | `rdfs:subClassOf` |
| 互斥类型公理 | `owl:disjointWith` |
| 不可自反／非对称／函数性公理 | `owl:IrreflexiveProperty` 等 |
| 必填属性 | `sh:minCount 1` |

**SHACL 形状由声明生成，绝不手写。** 手写的一份会与它本应镜像的发布门禁漂移，
而漂移后的形状会声明平台并不执行的约束——消费方会拿它校验并相信结果，
这比不提供形状更糟。

**明确不导出**需要 DL 推理才有意义的构件：`owl:equivalentClass`、属性链、
蕴含未见实例存在的基数限制。ADR-0005 拒绝 DL 推理的理由不变——
由包含推理得出的结论无法回溯到某个人做过的声明，而可回溯性是本平台的产品本身。

**采用 OWL 作为词汇、同时拒绝 OWL 推理，是一个自洽的立场**，
而标准对 OWL 的推荐是对前者的推荐。

## Consequences

发现并修掉了一个真实缺陷：**现有 Turtle 导出从上线起就无法被任何 RDF 解析器读取。**
前缀名的局部部分在 Turtle 中不能含 `/`，而导出发出的是 `bp:object/contract`。

测试没抓到它，因为断言的是输出**包含**某些子串——
而一个语法错误的文档包含子串的能力与合法文档毫无差别。
现在所有 RDF 导出测试都用真实解析器解析并查询结果图。
`rdflib` 因此进入 dev extra：平台只**写** RDF、从不读，
所以它是测试依赖而非运行时依赖，内核仍然零第三方依赖。

代价：`ontology_axiom` 表与 `standard_vocabulary.py` 模块，
以及公理表在 `check_axioms` 中每次发布评估都会被读一次。
缺表按「未声明任何公理」处理而非报错——
否则升级时每次发布评估都会失败，而那正是让一个特性被回滚的失效模式。

被否决的方案：

- **把公理表达为一种特殊的规则类型。** 复用了存储，但丢掉了区别本身：
  公理不针对实例，把它塞进规则求值路径意味着它需要一个实例才能被检查。
- **替换 `ont:` 词汇为纯 OWL。** 破坏性变更，且会丢掉标准词汇无对应词的字段。
- **手写 SHACL 形状文件。** 见上：会漂移，且漂移后会说谎。
- **引入 `rdflib` 做运行时序列化。** 内核零依赖是明确承诺；
  写 Turtle 是字符串拼接就能正确完成的事，前提是有解析器在测试里守着。

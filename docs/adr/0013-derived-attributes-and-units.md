# ADR-0013 派生属性与单位量纲

- 状态：Accepted
- 日期：2026-08-23

## Context

ROADMAP 通用性 #7（派生属性）与 #10（单位与量纲）。两项在实现上是同一个机制，
因此合并为一份 ADR。

### #7 计算逻辑被复制到每条规则里

每个属性都是存储列的镜像，业务计算出来的量只能在用到它的每条规则里重算：

```
毛利率      = (revenue - cost) / revenue
合同剩余额度 = credit_limit - customer_active_total
```

同一个定义抄进五条规则，业务口径变更时就有五处要改、五处可能不一致。

### #10 没有单位的数字不是业务值

`amount = 1000` 在「一张表存元、另一张存万元」的库里没有含义。具体的失败是：

```
合同金额（万元）> 客户额度（元）
```

按 `500 > 1000000` 求值为假，而事实是额度被超了五倍。
**这是用正确数据产出的错误判定**，正是 ADR-0002 要防的那类失败。

## Decision

### 派生属性就是普通属性

存为 `business_attribute` 行，只是 `derived_expression` 非空。
对所有消费方——规则、解释、图谱视图、导出、前端——它与映射属性无差别，
只有取值来源不同。这样不需要为「计算字段」单独开一条链路。

### 派生表达式复用规则沙箱

同一个 AST 白名单沙箱，同一个静态校验。**第二个求值器会漂移，
而两者中较松的那个就会成为突破口。**

沙箱是**注入**进 `derived_attributes` 的，不是 import 进去的：
该模块是叶子，内核依赖它。反向 import 会造出技术债第 3 项记的那类环——
分包（阶段 E）时跨包的环无法用函数内 import 化解。

### 多趟求值，深度封顶

一个派生属性可以引用另一个，且**不要求声明顺序**——UI 里的声明顺序不该是
业务人员需要推理的东西。每趟求值把当轮可算的算出来，一趟没有进展即停止。

深度封顶而非做依赖图求解：更深的链条几乎必然是建模错误，
而无界求解器遇到循环定义不会终止。

### 单位换算走规范单位，跨量纲直接拒绝

N 个单位这样只需 N 个系数而不是 N²，且只有一处需要核对。

跨量纲（时长比质量）**抛错而不是原样返回数字**：那通常意味着建模有误，
而静默透传会让由此得出的判定看起来完全有效。

### 货币只管刻度，不管汇率

`currency` 量纲覆盖元／万元／亿元这类刻度换算。汇率被刻意排除在外：
汇率是随时间变化的数据，内嵌一个汇率会让判定不可复现（ADR-0005）。

### `Quantity` 继承 float

存储量值上的一切算术、聚合与 JSON 序列化都不变。改变的只有比较：
比较前先换算。

对裸数字的比较仍是普通比较。规则里的字面量（`amount > 0`）没有单位可换算，
拒绝它会破坏所有既有规则；其含义是「以该属性自身的单位计」，
这也正是规则作者在模型里看到的。

### 派生值算不出来时缺席，而不是 None

注入 `None` 会让 `margin > 0.1` 求值为 False，
**与真实违规完全无法区分**。缺席则触发 `NameError`，
由内核转为「未通过 + 原因」。

### 不允许把映射属性改成派生属性

否则会静默改变每条读取该名字的规则所依据的值。要求换编码或先解除映射。

## Alternatives considered

**给派生属性单独建表。** 被否决：所有消费方都要改，且「它是不是属性」
会变成每个查询都要回答的问题。

**为派生表达式写单独的求值器。** 被否决：两个沙箱会漂移，较松的成为突破口。

**在派生模块里 import 内核。** 被否决：造环，分包时变成硬错误。改为注入。

**做完整的依赖图求解。** 被否决：多趟求值 + 深度封顶已覆盖真实用例，
且循环定义时必然终止。

**单位不匹配时静默换算或静默忽略。** 被否决：换算跨量纲无意义，
忽略则退回错误判定。同量纲换算，跨量纲报错。

**内置汇率换算。** 被否决：判定不可复现。

**比较裸数字时要求单位。** 被否决：会破坏所有既有规则，
且字面量本就没有单位可言。

## Consequences

正面：

- 业务口径只定义一次，改一处即全局生效
- 跨刻度比较得出正确结论，而非静默错误
- 派生属性随语义资产导出，下游可复现
- 单位声明是建模写操作并计入审计——单位变更会静默重新缩放所有阈值

负面：

- 每次评估都会计算该对象的全部派生属性，定义过多会拖慢判定
- 派生链条深度封顶为 5 趟，更深的定义需要拆分
- 单位靠人工声明：没人声明单位的库仍然退回普通数值比较
- `Quantity` 继承 float，因此在极端量级上受浮点精度限制；
  金额若需精确到分，应以分为单位存整数

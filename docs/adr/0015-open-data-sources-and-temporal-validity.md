# ADR-0015 数据源与写回通道开放，以及时态生效期

- 状态：Accepted
- 日期：2026-08-23

## Context

ROADMAP 通用性 #8（时态与生效期）、#12（数据源扩展）、#13（写回执行器扩展）。
这是通用性清单上最后三项。

### #12 三种数据库，且第三种加不进去

平台只支持 SQLite／PostgreSQL／MySQL。表面看是「少几个驱动」，
真正的障碍在扫描器里：方言差异写成了

```python
"""... where table_schema = current_schema() ..."""
if dialect == "postgresql"
else """... where table_schema = database() ..."""
```

**二元分支表达不了第三个数据库。** 要接 Oracle／SQL Server／达梦／人大金仓，
就必须改这 5 处扫描代码——也就是 fork，而这正是扩展注册表要避免的
（ADR-0007）。

更被忽略的是另两类：

| 场景 | 为何是刚需 |
|---|---|
| CSV 目录 | 部门的权威记录是共享盘上的夜间导出；被下线的系统只留下 CSV；**客户第一次评估这个平台时用的就是导出文件**，因为拿生产库凭据要走几周流程 |
| REST API | 没人会给你数据库访问权的系统：SaaS、支持合约内的厂商系统、数据库刻意私有的微服务 |

没有这两类，第一次评估根本无法发生。

### #13 写回只有 HTTP

这悄悄排除了本平台的目标客户：**大量遗留业务系统根本没有 API**，
它们的集成面就是一张可以插入的表，或者厂商让你调的存储过程。
拒绝这两者意味着平台能**判定**一个操作、然后无法**执行**它——
自动化闭环差最后一步。

### #8 只有当前值

实例的每个属性只有一个值。三类问题因此无法回答：

```
这份合同去年 12 月的金额是多少？
客户被拉黑之前签的合同要不要复核？
按签约时的信用额度，这份合同当时合规吗？
```

第三个才是关键。**合规判定通常是关于过去某一刻的**：
三月的审计问的是「一月那次放行，按一月已知的信息，对不对」。
拿今天的值重新判定回答的是另一个问题，且会给出一个自信的错误答案。

## Decision

### 方言差异声明为 profile，不写成分支

差异只有 6 个，且都是机械的：当前 schema 表达式、标识符引号、参数占位符、
分页语法、外键目录形状、目录标识符大小写。
抽成 `SqlDialect` 数据对象后，接一个新库变成声明几行。

`SqlDialect` **不执行 SQL**：它是值对象，所以第三方可以在平台没有对应驱动的
情况下声明方言，且 profile 可以脱离服务器做单元测试。

### 一个通用 DB-API 适配器，而不是每库一个

三个既有适配器几乎完全相同：差别只在导入哪个模块、如何把 URI 变成连接参数、
以及那 6 个方言细节。`information_schema` 是标准，扫描器可以完全共用。

于是新库是**声明**：`DriverSpec(source_type=..., dialect=..., module=...)`。
它随即获得元数据扫描、列剖析、外键发现、实例解析、全部规则能力与运行时读取。

**内置声明不默认激活。** Oracle 需要 `oracledb`，达梦的 `dmPython` 随客户端
提供、PyPI 上没有。把它们作为**声明**而非活动适配器发布，
意味着平台可以描述如何接入（`aletheia doctor` 列出哪些可用），
而不宣称一个它无法在 CI 里演示的支持。

**注册不要求驱动在场。** 类型会出现在接入列表里，
使用时给出「请安装 X」，而不是让人纳闷这个类型为什么不存在。

### CSV 与 REST：推断类型，但绝不推断外键

两者都没有可发现的模式，因此必须推断或声明。界线划在**能否可靠推断**：

| 项 | 处理 | 理由 |
|---|---|---|
| CSV 列类型 | 推断 | 类型是取值的性质，每次扫描同样得出；判错只是降级标签 |
| CSV 主键 | 推断，但要求数据证明唯一且完整 | 仅按名字推断会让 `fetch_one` 在取值重复时返回任意一行——实例身份静默指向错误记录 |
| CSV／REST 外键 | **不推断** | 关系语义（ADR-0012）建立在结构是声明的前提上；从命名巧合推出的关系，其基数与强弱无法解释 |
| REST 字段与类型 | **必须声明** | 从一次响应采样出的模式会随响应变化，引用它的判定不可复现 |

CSV 的外键候选会**上报**而不是采纳，让建模人员去声明真实的那些。

REST 若已有 OpenAPI 文档，可由它派生声明——那仍然是声明，
只是由 API 的所有者写的。

### 数据库写回：语句声明，值绑定

这是代码库中最危险的部分：它在判定之后运行，用平台的凭据，打向生产业务系统。
三条约束因此都不可选：

**语句是声明的，绝不由请求拼装。** 从操作载荷拼 SQL 会造出一个
从 HTTP 请求体可达的注入面。部署方注册具名 `SqlWriteback`（表、列，或显式语句），
请求只提供**值**，且一律绑定。

**单语句、有界。** 不允许分号与多语句；**没有 WHERE 的 UPDATE／DELETE 被拒绝**。
`update customers set status = 'x'` 少写一个 WHERE 就会改写整张表，
而等有人发现时，授权它的那次判定看起来完全合理。

**DDL 与 DELETE 默认拒绝。** 自动化用于推进业务状态，不用于变更结构或销毁数据。
确实需要删除的部署按写回逐条 opt-in，于是这个决定记录在声明里，
而不是由一个 URI 暗示。

**影响 0 行是失败。** UPDATE 匹配到 0 行意味着目标实例不在，或条件写错了。
「返回正常、什么也没改」是运维最难察觉的失败模式，因此默认按失败处理，
需要幂等的写回显式声明 `requireAffectedRows=False`。

**事务随操作结束。** 每次执行开连接、执行一条、提交、关闭。
参与他人事务的写回可能在判定记录已写「成功」之后被回滚，
留下与数据库相矛盾的留痕。

### 时态：区分有效时间与事务时间

| 时间线 | 回答什么 |
|---|---|
| 有效时间 valid time | 该事实在业务上何时为真 |
| 事务时间 transaction time | 平台何时得知 |

两者在数据迟到或被更正时不同，而在遗留系统集成里这是常态。
一次回溯更正改变了一月**为真**的内容，却没有改变一月平台**已知**的内容——
审计需要区分「我们按当时掌握的信息判断正确」与「信息本来就是对的」。
合并成一个时间戳会让这个区分无法恢复。

### as-of 精确，绝不插值

`as_of` 选取有效区间包含该时刻的版本。若无版本覆盖，该属性**缺席**，
而不是取最近邻——插值或取最近值会**编造一个从未被记录的事实并放进判定**。

区间取半开 `[from, to)`：若相邻两版本都能匹配边界时刻，
判定用了哪个值就取决于行顺序。

### 规则生效期跟随被判定的时刻

一月还没生效的规则不该去判一月的放行；已废止的规则仍要能解释它当年产出的判定。

### 无历史的属性保留当前值，不清空

丢弃它会把「这个字段我们没有历史」变成「这个字段当时为空」——
这是一个不同且虚假的断言。

### `coverage` 上报能回答的区间

平台只能记录它观测到的内容：一个原地覆盖值的源系统仍然丢掉了自己的历史。
明说这一点，好过暗示完整性。

## Alternatives considered

**引入 SQLAlchemy 解决方言问题。** 被否决：内核刻意零依赖。
要求客户为了嵌入一个语义层而安装 ORM，会显著提高它进入既有应用的门槛；
而读元数据的目的不是成为数据访问层。我们用约 200 行目录查询，
SQLAlchemy 是另一个量级的承诺。想用的部署可以注册一个基于它的适配器——
这正是适配器注册表的用途。

**每个数据库写一个专用适配器。** 被否决：三个既有适配器已经证明差异只有 6 处，
复制第四遍只会让这 6 处漂移。

**从 CSV 命名推断外键、从 REST 响应采样模式。** 被否决：
都会让模型建立在巧合或某一时刻的载荷上，判定不可复现。

**写回执行器接受请求提供的连接串。** 被否决：
那会让调用方把自动化指向任何可达的数据库。连接属于声明的通道。

**允许无 WHERE 的更新，靠文档警告。** 被否决：
代价与可见性不对称——出错时改写整张表，而授权它的判定看起来完全正常。

**用一个 far-future 哨兵日期表示开区间。** 被否决：
哨兵日期终会到来，届时所有比较会静默开始排除当前行。开区间存 NULL。

**as-of 无覆盖时取最近邻。** 被否决：编造事实。

**把有效时间与事务时间合并为一个时间戳。** 被否决：
回溯更正与迟到数据会变得无法区分，而这正是审计要问的。

## Consequences

正面：

- 接一个新 SQL 库从「改扫描器」变成「声明 4 行」，无需 fork
- CSV 与 REST 让第一次评估无需生产库凭据即可完成
- 没有 API 的遗留系统可以完成自动化闭环
- 回溯审计得到的是当时的答案，且判定记录写明是关于哪一刻
- 元模型闭合：对象、属性、关系、子类型、事件、状态、规则、**时态**均已实现

负面：

- 内置的 Oracle／SQL Server／达梦／人大金仓声明**未在 CI 中实测**：
  驱动与客户端库无法在 CI 环境安装。通用路径本身以真实 PostgreSQL 作为
  「一个平台没有专用适配器的库」实证，但具体方言细节需要首个真实部署确认
- CSV 每次查询整文件读取，适合导出规模，不适合仓库规模；`MAX_FILE_ROWS` 封顶
- REST 响应在单次判定内缓存，跨判定不缓存，因此高频判定会重复调用
- 属性历史只追加，长期运行需要归档策略，平台不提供
- 时态历史只覆盖平台观测到的区间，不能重建源系统丢失的历史
- 数据库写回需要部署方声明每一条语句，比「直接写 SQL」多一步——这是刻意的
